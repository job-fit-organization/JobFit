# Modular RAG

- RAG 시스템에서 성능을 높이기 위해 다양한 기술을 도입하는데, 이 기술들을 모듈화하여 도입함으로써 성능과 유연성을 모두 챙기는 방법
- 유연한 워크플로는 LangGraph를 사용하여 구현하기 적합
- 일반적인 검색 외에도, 생성한 답변을 평가하는 모듈을 중간중간 추가함으로써 답변의 신뢰도를 추적하며 필요시 추가적인 검색이나 답변 생성을 시도하도록 할 수 있음

## Corrective-RAG

- 사용자 질의에 대해, 벡터DB에서 검색된 문서로부터 생성한 답변이 검색된 문서와 얼마나 일치하는지 평가하는 모듈 추가
- 답변이 문서와 일치하지 않는다? -> 검색된 문서가 사용자 질의에 답변하기에 적합하지 않은 것이므로 웹 검색을 통해 필요한 문서 탐색
    - 기존의 사용자 질의를 검색에 적합한 형태로 재구성
- 답변이 문서와 일치한다? -> 검색된 문서가 사용자 질의에 답변하기에 적합한 것이므로 그대로 답변 생성

## Self-RAG

- 사용자 질의에 대해, 벡터DB에서 검색이 필요한지 아닌지를 판단하는 모듈 추가
- 검색이 필요하다고 판단되면 벡터DB에서 필요한 문서 탐색하고, 검색된 문서를 바탕으로 답변 생성
- 검색이 필요하지 않다고 판단되면 바로 답변 생성

## Supervisor Agents RAG  -> ReAct Agent RAG랑 차이점

- 각각의 특화된 작업을 담당하는 다수의 에이전트가 존재하며, 사용자 질의가 주어지면 supervisor agent가 적절한 작업 에이전트를 선택하여 작업을 할당하는 방식
- 다양한 에이전트가 모듈화된 형태로 존재할 수 있고, supervisor agent는 이들을 적절히 조합하여 유연한 워크플로를 구현
- ReAct Agent RAG는 하나의 에이전트가 여러가지 작업을 수행하지만, Supervisor Agents RAG는 여러 에이전트가 협업하는 방식
