# 검수 결과 — 경력자 강의자료
> Step 9: 조건식과 실전 SQL 작성법

### 검수 결과: ⚠️ 경미한 문제

**종합 의견**: 전반적으로 CASE/COALESCE/NULLIF/CAST 및 EXPLAIN 기반 성능 고려 같은 학습방향은 적절합니다. 다만 PostgreSQL 문법/구성 측면에서 몇 가지는 부정확하거나, “성능 고려”가 구체적 근거 없이 일반론처럼 제시되어 학습 목표 달성에 일부 제약이 있습니다.

**지적 사항**:
- **CASE 성능 고려 문구가 과도하게 일반적**입니다. “인덱스와 함께 사용할 경우 주의”는 원칙적으로 의미가 있을 수 있으나, 어떤 상황(예: 인덱스 사용성/표현식/조건 변형 등)에서 문제가 되는지 설명이 없어 오개념 유발 소지가 있습니다.
- **슬라이드 6 EXPLAIN 예시가 부정확**할 수 있습니다. `EXPLAIN ANALYZE`는 PostgreSQL에서 가능하지만, 학습용으로는 `EXPLAIN (ANALYZE, BUFFERS)` 등과 같은 형태/권장 설정이 더 명확합니다(단, 사실 오류는 아닙니다).
- **COPY 예시가 환경 의존적**입니다. `COPY employees FROM '/path/to/file.csv'`는 서버에 파일이 존재해야 하고 권한/설정이 필요하며, 일반 사용자/워크플로우를 가정하면 오해가 생길 수 있습니다(사실 오류라기보다 불완전한 안내).
- **NULL 처리 UPDATE 예시가 부분적으로 비효율/오해 소지**가 있습니다. `WHERE phone_number IS NULL`을 사용해 필수 조건은 맞지만, “NULL 처리 사례”의 의도가 있다면 `SET phone_number = COALESCE(phone_number, 'Unknown')`처럼 더 직접적인 형태로 제시하는 편이 학습에 더 도움이 될 수 있습니다(정확성 오류는 아님).
