# 검수 결과 — 경력자 강의자료
> Step 5: 집계와 보고서 SQL: GROUP BY, HAVING, 집합 연산

### 검수 결과: ⚠️ 경미한 문제

**종합 의견**: 전체 흐름과 SQL 개념(GROUP BY, HAVING, UNION/INTERSECT/EXCEPT, GROUPING SETS, CUBE/ROLLUP)은 대체로 정확하며 코드 예제도 문법적으로 무리가 없습니다. 다만 성능 최적화 슬라이드에서 “GROUP BY/HAVING에 인덱스 적용”과 같은 표현이 부정확할 수 있고, CUBE/ROLLUP 관련 설명이 ROLLUP의 “단계별 집계”를 제외하면 다소 포괄적으로 남아 학습자에게 혼동을 줄 여지가 있습니다.

**지적 사항** (있는 경우만):
- **성능 최적화(슬라이드 7)**: “인덱스 적용( GROUP BY 및 HAVING 절에 )”은 표현이 과도/부정확할 수 있습니다. HAVING은 보통 집계 후 필터라 인덱스로 직접 최적화되는 경우가 제한적이며, 실제 효과는 인덱스 종류·쿼리 조건·데이터 분포·실행계획에 좌우됩니다(일반화 표현으로 보완 필요).
- **CUBE와 ROLLUP 설명(슬라이드 6)**: 전반적으로 맞지만, ROLLUP이 생성하는 집계 레벨(부분합이 특정 순서로 누적됨) 같은 핵심 디테일이 부족해 경력자 기준으로 학습 목표(“다차원 집계 활용”) 달성에 약간 불리할 수 있습니다.
