# 검수 결과 — 경력자 강의자료
> Step 7: 데이터 변경과 무결성: INSERT, UPDATE, DELETE, Transaction

### 검수 결과: ⚠️ 경미한 문제

**종합 의견**: 전체 흐름(INSERT/UPDATE/DELETE/UPSERT/MERGE/트랜잭션/성능)이 잘 잡혀 있고 예제 SQL도 대부분 문법상 큰 오류는 없습니다. 다만 트랜잭션/오류 처리 및 MERGE 관련 설명·예제는 PostgreSQL 기준으로 정확히 동작하지 않거나 오해 소지가 있어 학습 목표 달성에 경미한 지장이 있습니다.

**지적 사항**:
- **슬라이드 7 트랜잭션 예제의 논리/문법 정확성**: `INSERT INTO accounts (balance) VALUES (100);`는 `accounts` 테이블에 보통 `id`(기본키)가 필요하므로 이후 `UPDATE ... WHERE id = 1;`와 연결되지 않습니다. 또한 `balance`만 insert하는 예제가 과도하게 일반적이라 실습 시 오류 가능성이 큽니다.
- **슬라이드 8의 ROLLBACK/IF 오류 처리 예제**: PostgreSQL에서 순수 SQL로는 `IF 오류 발생 THEN ... END IF;` 같은 제어문이 바로 실행되지 않습니다(PL/pgSQL 또는 어플리케이션/에러 핸들링 로직 필요). 이 부분은 “어떻게 구현하는지”가 불완전합니다.
- **슬라이드 6 MERGE 문법 도입 시 주의 부족**: PostgreSQL의 `MERGE` 지원 여부/버전 의존성이 있는데, 자료에 해당 전제가 없습니다. (환경이 다르면 문법 자체가 실패할 수 있어 학습 정확성이 떨어질 수 있습니다.)
- **슬라이드 2~4의 성능 최적화 문구는 일반론**: “더 효율적/WHERE 최적화 필요/인덱스 적용”처럼 방향성은 맞지만, 경력자 대상에 비해 근거가 부족해 학습 목표(실무 최적화까지) 달성은 다소 제한될 수 있습니다.
