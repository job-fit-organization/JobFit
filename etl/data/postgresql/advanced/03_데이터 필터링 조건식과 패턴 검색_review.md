# 검수 결과 — 경력자 강의자료
> Step 3: 데이터 필터링: 조건식과 패턴 검색

### 검수 결과: ⚠️ 경미한 문제

**종합 의견**: 전체적으로 WHERE, AND/OR, LIMIT/FETCH, IN/BETWEEN, LIKE, NULL, 복합 조건, 인덱스/EXPLAIN 등 기본 개념을 경력자 관점에서 무난하게 다루고 있어 학습목표 달성에는 큰 장애가 없어 보입니다. 다만 일부 표현이 PostgreSQL 기준으로는 불완전하거나(예: “FETCH”), 성능 관련 트레이드오프 설명이 과도하게 단정적으로 들리는 부분이 있습니다.

**지적 사항**:
- **슬라이드 4**: “LIMIT과 FETCH”라고 제목/표기하지만 예시는 `LIMIT`만 사용합니다. PostgreSQL의 `FETCH`(`OFFSET/FETCH FIRST`)를 다루는 설명이나 예시가 없어 제목과 내용 간 불일치가 있습니다.
- **슬라이드 3**: “복잡한 조건일수록 성능 저하”는 일반론으로는 맞을 수 있으나, 인덱스/통계/실행계획에 따라 달라질 수 있어 단정적으로 들립니다(오류는 아니나 설명이 다소 거칠어요).
- **슬라이드 9**: `EXPLAIN SELECT ...`는 맞지만, 실제 성능 최적화 관점에서는 `EXPLAIN (ANALYZE, BUFFERS)` 같은 확장 사용을 언급하지 않아 “쿼리 분석”의 완결성이 조금 떨어집니다(코드 정확성 문제는 아님).
