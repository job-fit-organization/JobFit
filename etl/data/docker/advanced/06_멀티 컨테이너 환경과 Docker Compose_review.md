# 검수 결과 — 경력자 강의자료
> Step 6: 멀티 컨테이너 환경과 Docker Compose

### 검수 결과: ⚠️ 경미한 문제

**종합 의견**: 전반적으로 Docker Compose의 개념/구조를 설명하는 흐름은 자연스럽고 큰 사실 오류는 보이지 않습니다. 다만 몇 가지 설명이 부정확하거나(Compose의 동작 원리, 버전/네트워크 표현), 코드 예제의 일관성이 부족해 학습 목표 달성에 약간의 혼선이 생길 수 있습니다.

**지적 사항** (있는 경우만):
- **Compose 동작 원리 설명이 다소 불완전**: “의존성으로 자동으로 시작 순서를 관리”라고 했지만, 기본 `depends_on` 외에도 헬스체크/ready 상태 보장 등과 혼동될 수 있게 뉘앙스가 일반적입니다(정확히는 “시작 순서”는 관리하지만 “준비 완료”를 자동 보장하진 않음).
- **`working_dir` / 커맨드 예제의 맥락 부족**: `app` 서비스에서 `working_dir: /app`과 `command: node server.js`를 쓰지만, 실제로 `/app/server.js`가 존재하도록 하는 `COPY`/볼륨 마운트 설정이 없어서 예제가 그대로 실행되기 어렵습니다(이미지로부터 제공되지 않는 한).  
- **`docker-compose.yml` 예시의 실무성 부족(네트워크 설정 등)**: `driver: bridge`는 일반적으로 사용되는 개념이지만, Compose에서 `networks: frontend`만으로도 충분한 경우가 많아 초보가 아닌 대상임에도 설명이 다소 단순화되어 있습니다.
- **`version: '3.8'` 표기 관련 여지**: 최신 Compose에서는 버전 필드가 선택 사항이거나 문맥에 따라 혼동을 줄 수 있어, “필수/정확한 권장”처럼 보일 여지가 있습니다.
