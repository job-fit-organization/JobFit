# 검수 결과 — 경력자 강의자료
> Step 3: Docker 아키텍처와 핵심 개념

### 검수 결과: ⚠️ 경미한 문제

**종합 의견**: 전반적인 구성과 핵심 개념(클라이언트-데몬, 이미지/컨테이너, 레이어 캐싱, 네트워킹, Compose)은 대체로 타당합니다. 다만 몇 가지 보안/아키텍처 설명이 부정확하거나(최소 권한·권한 드롭 예시), Compose의 사용 문법이 현재 버전 관점에서 다소 구식일 소지가 있습니다.

**지적 사항**:
- **보안 예시의 부정확성 가능**: `docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE ...`는 “최소 권한 원칙”을 설명하기엔 맥락이 약하고, 실제로는 애플리케이션이 필요한 권한/권한 범위에 따라 동작이 달라질 수 있습니다(예: 포트 바인딩 외에도 UID/GID, seccomp, userns 등 영향이 큼). “최소 권한”과의 직접 연결이 다소 부정확하게 느껴질 수 있습니다.
- **Compose `version: '3'` 표기**: Compose v2(현행 일반 사용)에서는 `version` 필드가 필수/유효하지 않은 경우가 많아, 예시가 다소 구식 문법처럼 보일 수 있습니다.
- **네트워킹 설명의 과단순화**: “각 컨테이너는 고유한 IP와 네트워크 인터페이스를 가짐”은 대체로 맞지만, “고유 IP”가 항상 동일한 형태로 보장되는지(네트워크 모드/구성에 따라 달라짐)까지는 고려가 덜 되어 있어 설명이 약간 단정적으로 보입니다.
