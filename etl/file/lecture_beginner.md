# 🐳 Docker, 쉽게 이해하기: 개발의 첫걸음 가이드

## 👨‍🎓 초보 학생 및 비전공자 대상 강의 자료

---

### 🖼️ Slide 1: 표지 및 목표 설정

**제목:** 🐳 Docker, 어렵지 않아요! (개발의 '격리' 기술 배우기)
**부제:** 개발자가 코드를 돌리는 마법의 상자 원리 알아보기

**💡 오늘 배울 것 (Goal):**
*   Docker가 무엇이고 왜 필요한지 이해합니다.
*   개발 환경이 어떻게 격리(Isolation)되는지 핵심 개념을 잡습니다.
*   복잡한 원리보다는, 우리가 `docker run` 같은 명령을 쳤을 때 *어떤 과정*이 일어나는지만 알아봅니다.

**🧭 기대 효과:**
*   "내 컴퓨터에서는 되는데 서버에서는 안 되는 문제"의 개념을 명확히 이해합니다.

---

### 🖼️ Slide 2: ❓ 왜 Docker가 필요할까요? (문제 정의)

**제목:** 🚧 개발 환경 불일치 문제: "내 컴퓨터에서는 잘 됐는데?"
**핵심 문제:**
*   개발자 A의 노트북 OS 버전 (Win 10)
*   개발자 B의 노트북 OS 버전 (Mac OS)
*   회사 서버의 환경 (Linux)
**결과:** 코드는 같아도, 운영체제나 라이브러리 버전 차이 때문에 작동하지 않는 문제가 발생합니다. (❌)

**🎯 Docker의 해결책: 컨테이너(Container)**
*   컨테이너는 **작동에 필요한 모든 것** (코드, 라이브러리, OS 설정)을 하나로 묶어 포장합니다.
*   포장된 컨테이너는 어떤 환경(Mac, Win, Linux)에 놓여도 **똑같이, 완벽하게** 작동합니다. (✅)

> **🔑 핵심 개념:** Docker는 애플리케이션을 **'상자'**에 담아 전 세계 어디서든 똑같이 돌릴 수 있게 해주는 기술입니다.

---

### 🖼️ Slide 3: 📦 핵심 개념 이해하기: Image vs. Container

**제목:** 🖼️ 설계도(Image) vs. 작동하는 제품(Container)
**🔍 이미지 (Image):**
*   **비유:** 건물의 **'청사진'** 또는 '재료 꾸러미'
*   **정의:** 애플리케이션을 실행하는 데 필요한 모든 명령어와 파일들이 담긴 **'읽기 전용 템플릿'**입니다.
*   **특징:** 가볍고, 수정하기 어렵습니다. (버전 관리 용이)

**⚙️ 컨테이너 (Container):**
*   **비유:** 청사진을 바탕으로 **'실제로 지어진 집'**
*   **정의:** 이미지를 바탕으로 **실행되고 있는, 살아있는 프로세스(인스턴스)**입니다.
*   **특징:** 격리되어 다른 컨테이너나 호스트 컴퓨터에 영향을 주지 않습니다.

**✅ 요약:**
| 개념 | 역할 | 비유 |
| :--- | :--- | :--- |
| **Image** | 📦 틀/설계도 (Template) | 레고 설명서 |
| **Container** | 🏠 실제 작동하는 시스템 | 조립된 레고 제품 |

### 🖼️ Slide 4: 🏗️ Docker 시스템 구성요소 (The Three Pillars)

**제목:** ⚙️ Docker가 돌아가는 세 가지 주체
**1. Docker Client (사용자 인터페이스)**
*   **역할:** 우리가 사용하는 터미널 명령어 (`docker run`, `docker build`)입니다.
*   **비유:** 리모컨. 사용자가 명령을 내립니다.
*   **행동:** "저런 앱(Image)을 실행해줘!" 라고 요청합니다.

**2. Docker Daemon (백그라운드 엔진)**
*   **역할:** 실제로 모든 작업을 처리하는 강력한 엔진 (뇌).
*   **비유:** 공장 관리자. 요청을 받고, 이미지를 가져오고, 컨테이너를 생성/관리합니다.
*   **행동:** 요청을 받아, 이미지를 찾고, 컨테이너를 격리 공간에 배치합니다.

**3. Docker Host (실행 환경)**
*   **역할:** 컨테이너가 실제로 돌아가는 컴퓨터(PC 또는 서버).
*   **구성:** 운영체제(OS)와 그 위에 올라가서 돌아가는 Docker Daemon 엔진이 있습니다.
*   **핵심:** 이 호스트가 곧 격리된 놀이터를 제공하는 땅입니다.

---

### 🖼️ Slide 5: 🌐 Image를 어디서 가져오나요? (Registry)

**제목:** 📚 Docker 이미지 저장소: Registry
**무엇인가요?**
*   Docker 이미지를 저장하고 배포하는 거대한 '온라인 창고'입니다.

**📍 대표적인 저장소:**
1.  **Docker Hub (공개 레지스트리):**
    *   전 세계 개발자들이 만든 수많은 이미지가 모여있는 공공 창고입니다. (가장 많이 사용)
    *   예: Nginx 웹 서버 이미지, Python 이미지 등
2.  **Private Registry (사설 레지스트리):**
    *   회사나 특정 조직이 보안상 내부적으로만 사용하기 위해 만드는 창고입니다.
    *   예: 우리 회사만 사용할 비밀 앱 이미지

**🚀 작동 원리:**
1.  `docker pull nginx`: Docker Client가 Daemon에게 **"Nginx 이미지(Blueprint)를 가져와줘"** 라고 요청합니다.
2.  Daemon은 Registry(Docker Hub)에 접속하여 Nginx 이미지를 다운로드 받아 Host에 저장합니다.

---

### 🖼️ Slide 6: 🛠️ 실행 과정 추적: `docker run`은 어떻게 작동할까요?

**제목:** 🔄 마법의 순서: `docker run` 실행 과정
**명령어:** `docker run -p 80:80 nginx` (Nginx 앱을 실행해라)

**1. 요청 (Client → Daemon):**
*   Client가 "Nginx 컨테이너를 띄워줘"라고 명령을 보냅니다.

**2. 준비 (Daemon & Registry):**
*   Daemon은 Nginx 이미지를 로컬에 있는지 확인합니다.
*   없으면, Registry(Docker Hub)에서 Nginx 이미지를 다운로드합니다.

**3. 격리 및 실행 (Host Kernel):**
*   Daemon은 이미지를 기반으로 **'격리된 공간(Container)'**을 만들어냅니다.
    *   *(기술적 설명 회피: 이 공간 덕분에 Nginx가 아무리 문제가 생겨도 내 컴퓨터는 안전합니다.)*
*   컨테이너가 실행되며, 우리가 요청한 포트(Port 80)로 외부와 통신할 수 있게 연결됩니다.

**💡 최종 결과:** Nginx가 완벽하게 작동하는 독립적인 상자가 만들어집니다!

### 🖼️ Slide 7: 💾 데이터 관리와 영속성 (Persistence)

**제목:** 💾 컨테이너가 죽어도 데이터는 살아남게 하는 방법
**문제:** 일반 컨테이너는 임시적인 존재입니다. 컨테이너를 삭제하면 그 안에 저장했던 데이터도 **싹 사라집니다.** (😢)

**✅ 해결책: 볼륨 (Volume)**
*   **개념:** 컨테이너 외부, 호스트 컴퓨터의 파일 시스템에 데이터를 따로 보관하는 전용 공간입니다.
*   **작동 방식:** 컨테이너가 데이터를 쓰더라도, 실제로는 이 볼륨 공간에 기록됩니다.
*   **장점:** 컨테이너는 사라져도 **데이터는 영원히 안전**하게 남아 다음 컨테이너에서 재사용할 수 있습니다.

**[다른 방식] 바인드 마운트 (Bind Mount):**
*   개발할 때 유용합니다. 내 컴퓨터의 폴더(소스 코드)를 컨테이너 내부로 연결하여, 코드를 수정하면 컨테이너가 즉시 반영하게 합니다.

---

### 🖼️ Slide 8: 🌐 네트워크와 통신 (Networking)

**제목:** 🔗 컨테이너들끼리 어떻게 대화할까요?
**핵심 개념:** 컨테이너들은 기본적으로 서로 격리되어 독립적인 공간에 있습니다. 통신을 위해서는 특별한 연결 방식이 필요합니다.

**🌐 네트워크 유형 (Network Types):**
1.  **Bridge (브릿지):**
    *   **가장 일반적:** 여러 컨테이너들이 마치 같은 로컬 네트워크에 있는 것처럼 통신하게 해주는 다리 역할을 합니다. (서로 대화할 수 있게 함)
2.  **호스트(Host):** 컨테이너가 마치 호스트 컴퓨터의 일부처럼 직접 네트워크 자원을 사용하게 합니다. (최대 성능 확보)

**💡 정리:** 컨테이너들이 혼자 고립되지 않고, `Docker`라는 다리(Bridge)를 통해 서로 연결되고 통신할 수 있게 만드는 것이 가장 중요합니다.

### 💡 복습 요약 (세 줄 정리)

1.  **컨테이너란?**: 애플리케이션이 돌아가는 데 필요한 모든 것(코드, 라이브러리, 설정)을 **하나의 완벽한 상자(패키지)**에 담아 격리시킨 것.
2.  **작동 원리**: 격리된 상자를 **(Docker)** 이라는 엔진을 통해 실행하여, 어떤 컴퓨터(개발자 PC, 클라우드 서버) 위에서든 **항상 동일한 환경**을 보장.
3.  **핵심 장점**: "내 컴퓨터에서는 되는데, 서버에서는 안 돼요"라는 문제를 **완벽하게 해결**해주는 것이 가장 큰 강점입니다.
